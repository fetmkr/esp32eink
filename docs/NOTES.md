# 실측 기록

XIAO ESP32-S3 Plus + Seeed EE05 보드 + Good Display GDEY0426T82 (4.26인치, 800x480, SSD1677)

측정 날짜 2026-08-19. 모두 이 보드에서 직접 재거나 원문에서 확인한 것이다.

## 핀

회로도 `schematic/XIAO_ePaper_Display_Board_EE05_V1.0_SCH.pdf` 와
Arduino esp32 코어 `variants/XIAO_ESP32S3_Plus/pins_arduino.h` 에서 확인.

| 신호 | XIAO 핀 | GPIO | FPC 핀 |
|---|---|---|---|
| SCK | D8 | 7 | 12 |
| MOSI | D10 | 9 | 11 |
| CS | D7 | 44 | 13 |
| DC | D16 | 10 | 14 |
| RST | D11 | 38 | 15 |
| BUSY | D3 | 4 | 16 |
| 패널 전원 | D6 | 43 | 보드 내부 |
| 버튼1 | D1 | 2 | KEY 블록 K2 |
| 버튼2 | D2 | 3 | KEY 블록 K3 |
| 버튼3 | D9 | 8 | KEY 블록 K4 |
| LED | - | 21 | XIAO 모듈 위, 활성 LOW |

D6(GPIO43)을 HIGH 로 안 올리면 BUSY 가 안 풀린다.

## 갱신 시간

| 방식 | 그림 보내기 | 갱신 | 눈에 보이기까지 |
|---|---|---|---|
| 전체 (800x480) | 183ms | 1700ms | 1.88초 |
| 부분 (800x480) | 92ms | 405ms | 0.50초 |
| 부분 (시계 칸만 256x44) | 3ms | 406ms | 0.42초 |

- 갱신 시간은 창 크기와 무관하다. 480줄이든 60줄이든 407ms 로 같다.
- 전체 갱신 1700ms 는 이미 빠른 쪽 파형이다. `useFastFullUpdate = true`.
  규격상 보통 전체는 3.5초, 빠른 전체는 1.5초.

## SPI 속도

GxEPD2 기본값은 4MHz (`GxEPD2_EPD.cpp` 24줄).

| 속도 | 48000바이트 보내기 |
|---|---|
| 4MHz | 180ms |
| 8MHz | 124ms |
| 16MHz | 96ms |
| 20MHz | 90ms |
| 26MHz | 91ms |

20MHz 위로는 안 빨라진다. 바이트를 하나씩 보내는 함수 호출 비용이 벽이다.
한 바이트에 1.9마이크로초인데 선로에 실리는 시간은 0.4마이크로초뿐이다.

## 하면 안 되는 것

### GxEPD2 의 writeImageAgain 을 줄이지 말 것

`drawImage` 는 안에서 이렇게 돈다.

    writeImage      -> refresh -> writeImageAgain

`writeImageAgain` 은 이전 화면(0x26)과 현재 화면(0x24) 두 곳에 다 쓴다.
전송을 아끼려고 `writeImageToPrevious`(0x26 만) 로 바꾸면 다음 부분 갱신이
엉뚱한 차이를 계산해서 화면이 겹쳐 보인다. 실제로 그렇게 만들었다가 되돌렸다.

### 부분 갱신을 두 걸음으로 나누지 말 것

"창을 바탕색으로 한 번 민 뒤 내용을 그리면 시작 상태가 깨끗해진다"고 예상해서
만들었는데, 미는 동작이 눈에 그대로 보여서 숫자가 깜박였다. 기본 한 걸음이 맞다.

## 온도로 파형 고르기 — 이 패널에는 안 통함

데이터시트 6.9절: 칩 안 OTP 에 파형이 34벌 있고 온도로 고른다.
0x22 의 0x20 비트를 끄면(0xFC 대신 0xDC) 0x1A 로 써넣은 온도가 쓰인다.
GxEPD2 도 전체 갱신을 빠르게 할 때 이 수법을 쓴다 (0x1A 에 0x5A = 90도).

실측: -20도부터 40도까지 바꿔도 갱신 시간이 418ms 로 똑같았고 화면도 같았다.
이 패널은 부분 갱신 파형을 한 벌만 담고 있다.

## 파형을 직접 써넣기 — 되긴 됨

데이터시트 Figure 6-6, Table 6-5, Table 6-6 참고. `src/epd_tune.h` 에 정리해 뒀다.
0x32 로 105바이트를 쓰고 0x22 에 0xCC 를 주면 내 파형이 쓰인다.
실측 1294ms. 동작은 확인했으나 지금은 쓸 일이 없다.

## 한글

Adafruit_GFX 의 폰트 구조체는 글자를 끊김 없는 한 구간으로만 담는다
(`gfxfont.h` 의 first, last). 한글 완성형은 11172자라 못 담는다.
글자 위치를 가리키는 값도 16비트라 65535바이트를 못 넘는다.

그래서 쓰는 글자만 골라 담고 코드포인트로 이진 탐색하는 표를 따로 만들었다.
`src/kfont.h`, `tools/build_fonts.py`. 폰트는 Pretendard (SIL OFL).

## 시계 건너뛰기 (2026-08-19 측정)

3분 동안 재보니 정확히 3번, 전부 60초 지점, 전부 3초씩 건너뛰었다.

    59.5s  10 -> 13 (3초)
   120.5s  11 -> 14 (3초)
   181.5s  12 -> 15 (3초)

원인은 잔상 털기(전체 갱신)다. 2.06초가 걸리는 동안 시계가 멈추니 3초를 건너뛴다.
그 밖에 불규칙한 건너뛰기는 없었다. 더 크게 건너뛴 것은 시리얼을 열거나 펌웨어를
올려서 보드가 리셋됐을 때였다.

### 정한 값

부분 갱신 300번(5분)마다 전체 갱신 한 번.
제조사 권고(5~6번마다)보다 50배 넉넉하다. 사용자가 초 표시를 유지하기로 정했다.
잔상이 눈에 거슬리면 줄인다. 시리얼로 `G<숫자>` 를 보내면 바로 바뀐다.

전자잉크 시계 프로젝트들은 대개 초를 안 보여준다.
1분마다 부분 갱신, 1시간마다 전체 갱신이 흔한 방식이다.

## 시계가 멈춰 보이던 진짜 원인 — 시리얼 출력 (2026-08-19)

증상: 시계가 뜨문뜨문 가다가 멈춤. 그런데 시리얼을 열어 읽고 있으면 잘 감.

원인은 화면이 아니라 USB 출력이었다.

    // HWCDC.cpp
    static uint32_t tx_timeout_ms = 100;
    const uint32_t max_consec_timeouts = 20;   // 100ms x 20 = 최대 2초

USB 가 꽂혀 있는데 아무도 읽어가지 않으면 출력 버퍼가 차고, Serial.printf 한 번이
최대 2초까지 멈춰 선다. 시계가 1초마다 두 줄을 찍고 있었으니 (GxEPD2 진단 줄과
내가 넣은 줄) 한 번에 최대 4초를 붙잡혔다.

### 고친 것

    Serial.setTxTimeoutMs(0);         // 안 나가면 기다리지 말고 버린다
    display.init(0, true, 2, false);  // 첫 인자 0 = GxEPD2 진단 출력 끔
    bool clockLog = false;            // 시계 로그 기본 끔. 시리얼 p 로 켠다

### 검증

포트를 닫고 116초 뒤 다시 열어 눈금을 비교했다.

    닫기 직전   16:41:05  눈금 11
    다시 열 때  16:43:01  눈금 127

116초에 116눈금. 하나도 안 빠졌다. 보드는 리셋되지 않았고 시각과 바탕색도 유지됐다.

### 교훈

증상만 보고 화면 문제라고 단정해서 잔상, 파형, 온도까지 파고들었다.
